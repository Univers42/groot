# osionos assistant modes: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (or superpowers:executing-plans) to carry out this plan task by task. Every step is a checkbox (`- [ ]`). Do not skip a failing-test step.

**Goal:** a conversation can be in `manual`, `plan`, `accept_edits` or `auto` mode. In the two auto modes, `add_blocks`, `rename_page` and `create_page` are applied by the server without a card:
- through the existing single gate;
- with the run request's own token;
- under taint, anchor, workspace, cap and allowlist checks;
- recorded with `decided_by`, and each can be undone for 7 days.

**Architecture:**
- `proposeWrite` still inserts every row.
- A new `autoDecide` either claims the row and runs it through one extracted `applyClaimed` core, which `decideApproval` also uses, or falls back to today's card.
- The mode is a server-side column on the conversation. The run snapshots it at start, and each decide reads it again live and keeps the narrower of the two.
- Provenance taint is a sticky column, set when content is read (the `markWebTaint` pattern).

**Tech Stack:**
- osionos-ai service: TypeScript, node `http` routes, `pg`, `ioredis`, AI SDK tool loop. Tests run with the service runner (`scripts/ci.sh`).
- Web app: React, with `tests/canvas` (node:test plus `renderToStaticMarkup`) and Playwright on a production build.
- Postgres migrations live in `groot/models`.

## Review Focus

1. One gate: only `approvals/apply.ts`, `approvals/applyAppend.ts`, `approvals/undoApplied.ts` and `builders/*` import `bridgeWrite`. Auto rows always pass through `proposeWrite` first.
2. Every auto refusal becomes a card with a `cardReason`, never an error. Mode and anchor are read live at decide time and narrowed against the run snapshot.
3. Taint fails closed: an unknown tool, a missing page, an attachment, a thread, or a foreign skill or agent each set `provenance_tainted_at` before the model sees the content.
4. A claimed row always finishes: abort and the 120 s timeout stop new claims only, and no test leaves a row in `executing`.
5. Undo never forces: every inverse is a version-preconditioned write or a compare-then-write with its R3 caveat, and any drift becomes `changed_since`.
