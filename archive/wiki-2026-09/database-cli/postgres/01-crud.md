# CRUD — Create, Read, Update, Delete

After this file you can build a normalized schema from scratch, insert rows with automatic
primary keys, query across joins and aggregates, update records, and upsert without duplicates
— all via `docker exec` one-shot commands.

## Prerequisite

```bash
# Create the scratch database once (see 00-connect.md)
docker exec mini-baas-postgres sh -lc \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "CREATE DATABASE learn_cli;"'
```

## CREATE TABLE — the shop schema

### customers

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
CREATE TABLE customers (
  id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name       TEXT NOT NULL,
  email      TEXT NOT NULL UNIQUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);"'
```

`GENERATED ALWAYS AS IDENTITY` is the modern standard (PostgreSQL 10+). It creates a sequence
behind the scenes and ties it to the column. `ALWAYS` means you cannot bypass it with an
explicit value — use `GENERATED BY DEFAULT` if you need to insert known IDs during migrations.

### products

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
CREATE TABLE products (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name        TEXT NOT NULL,
  price_cents INT  NOT NULL CHECK (price_cents >= 0),
  stock       INT  NOT NULL DEFAULT 0 CHECK (stock >= 0)
);"'
```

Storing money as integer cents avoids floating-point rounding. `CHECK` constraints are
enforced by the server on every write.

### orders — with foreign keys

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
CREATE TABLE orders (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id BIGINT NOT NULL REFERENCES customers(id),
  product_id  BIGINT NOT NULL REFERENCES products(id),
  qty         INT    NOT NULL CHECK (qty > 0),
  status      TEXT   NOT NULL DEFAULT '"'"'pending'"'"',
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);"'
```

`REFERENCES customers(id)` creates a foreign-key constraint. PostgreSQL will reject any order
row whose `customer_id` does not exist in `customers.id`.

## INSERT

### Single row

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
INSERT INTO customers (name, email)
VALUES ('"'"'Alice Martin'"'"', '"'"'alice@example.com'"'"')
RETURNING id, name;"'
```

`RETURNING` echoes server-generated values (like `id`) back to the caller without a separate
`SELECT`. Critical for capturing auto-generated IDs in scripts.

### Multi-row INSERT with RETURNING

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
INSERT INTO customers (name, email) VALUES
  ('"'"'Bob Chen'"'"',    '"'"'bob@example.com'"'"'),
  ('"'"'Carla Diaz'"'"', '"'"'carla@example.com'"'"')
RETURNING id, name;"'
```

```
 id |     name
----+-----------
  2 | Bob Chen
  3 | Carla Diaz
```

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
INSERT INTO products (name, price_cents, stock) VALUES
  ('"'"'Notebook'"'"', 1299, 50),
  ('"'"'Pen Set'"'"',   499, 200),
  ('"'"'Desk Lamp'"'"', 3999, 15)
RETURNING id, name, price_cents;"'
```

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
INSERT INTO orders (customer_id, product_id, qty, status) VALUES
  (1, 1, 2, '"'"'paid'"'"'),
  (1, 3, 1, '"'"'paid'"'"'),
  (2, 2, 5, '"'"'pending'"'"'),
  (3, 1, 1, '"'"'shipped'"'"')
RETURNING id, customer_id, product_id, qty, status;"'
```

## SELECT

### Basic WHERE

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
SELECT id, name, email FROM customers WHERE name LIKE '"'"'A%'"'"';"'
```

### JOIN across all three tables

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
SELECT c.name AS customer,
       p.name AS product,
       o.qty,
       o.status,
       (o.qty * p.price_cents) AS total_cents
FROM orders o
JOIN customers c ON c.id = o.customer_id
JOIN products  p ON p.id = o.product_id
ORDER BY o.id;"'
```

Expected:
```
   customer   |  product  | qty | status  | total_cents
--------------+-----------+-----+---------+-------------
 Alice Martin | Notebook  |   2 | paid    |        2598
 Alice Martin | Desk Lamp |   1 | paid    |        3999
 Bob Chen     | Pen Set   |   5 | pending |        2495
 Carla Diaz   | Notebook  |   1 | shipped |        1299
```

### GROUP BY + aggregate

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
SELECT c.name,
       COUNT(o.id) AS order_count,
       SUM(o.qty * p.price_cents) AS total_spent_cents
FROM orders o
JOIN customers c ON c.id = o.customer_id
JOIN products  p ON p.id = o.product_id
WHERE o.status != '"'"'pending'"'"'
GROUP BY c.name
ORDER BY total_spent_cents DESC;"'
```

```
     name     | order_count | total_spent_cents
--------------+-------------+-------------------
 Alice Martin |           2 |              6597
 Carla Diaz   |           1 |              1299
```

### LIMIT / OFFSET for pagination

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
SELECT id, name FROM customers ORDER BY id LIMIT 2 OFFSET 0;"'
```

Always pair `LIMIT` with `ORDER BY`; without ordering, PostgreSQL may return rows in any
sequence and pagination becomes unpredictable.

## UPDATE

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
UPDATE orders
SET status = '"'"'shipped'"'"'
WHERE id = 3
RETURNING id, status;"'
```

```
 id | status
----+---------
  3 | shipped
```

`RETURNING` works on UPDATE and DELETE too — use it to confirm exactly which rows changed.

## DELETE

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
DELETE FROM orders WHERE status = '"'"'shipped'"'"' AND id = 4 RETURNING id;"'
```

## UPSERT — INSERT ... ON CONFLICT DO UPDATE

Insert a customer; if their email already exists, update the name instead of raising an error:

```bash
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
INSERT INTO customers (name, email)
VALUES ('"'"'Alice M. (updated)'"'"', '"'"'alice@example.com'"'"')
ON CONFLICT (email) DO UPDATE
  SET name = EXCLUDED.name
RETURNING id, name, email;"'
```

```
 id |       name        |       email
----+-------------------+-------------------
  1 | Alice M. (updated)| alice@example.com
```

`EXCLUDED` refers to the row that would have been inserted. The `ON CONFLICT` clause requires
a conflict target — the unique column(s) or a named constraint.

## Scenario: full shop session

```bash
# 1. Seed data (all steps above)
# 2. Check total revenue by product
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
SELECT p.name,
       SUM(o.qty)                   AS units_sold,
       SUM(o.qty * p.price_cents)   AS revenue_cents
FROM orders o
JOIN products p ON p.id = o.product_id
GROUP BY p.name
ORDER BY revenue_cents DESC;"'
```

```
  product  | units_sold | revenue_cents
-----------+------------+---------------
 Desk Lamp |          1 |          3999
 Notebook  |          3 |          3897
 Pen Set   |          5 |          2495
```

```bash
# 3. Mark all pending orders shipped
docker exec mini-baas-postgres sh -lc 'psql -U "$POSTGRES_USER" -d learn_cli -c "
UPDATE orders SET status = '"'"'shipped'"'"' WHERE status = '"'"'pending'"'"' RETURNING id, status;"'
```

## Gotchas / Docker notes

- **Shell quoting**: passing single quotes inside `sh -lc '...'` requires `'"'"'` (end the
  outer single-quote, inject a literal `'`, reopen the outer single-quote). In a `.sql` file
  executed via `psql -f`, normal SQL quoting applies — much cleaner.
- **Identity columns reject explicit IDs**: `GENERATED ALWAYS AS IDENTITY` will error if you
  pass an explicit value for `id`. Use `GENERATED BY DEFAULT AS IDENTITY` when you need to
  seed known IDs (e.g., restoring a dump).
- **CHECK constraints are not deferred**: they fire immediately on each row, not at commit
  time. If you need deferred constraint checking, use a foreign key with `DEFERRABLE`.
- **RETURNING is server-side**: it adds no extra round-trip — the server computes it as part
  of the write.
