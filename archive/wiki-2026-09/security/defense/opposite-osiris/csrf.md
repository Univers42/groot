# CSRF Mitigation — opposite-osiris (marketing + auth website)

> Cross-site request forgery against the auth gateway is blocked by three layered controls: a `SameSite=Lax` `HttpOnly` cookie that browsers refuse to send on cross-site POSTs, a strict single-origin CORS allowlist that prevents credentialed cross-origin preflight from resolving, and a per-request Cloudflare Turnstile token on all state-changing auth actions that an attacker cannot replay or forge.

## What it is (the concept)

**Cross-Site Request Forgery (CSRF)** is an attack in which a malicious page causes an authenticated user's browser to send a state-changing request to a target origin, piggy-backing on that browser's stored credentials. The two classical mitigations are **SameSite cookie attributes** — which instruct the browser not to attach the session cookie on cross-site navigations — and **synchronizer tokens** (or equivalent per-request secrets) that only the legitimate front-end can supply. A correctly configured **CORS policy** provides a complementary browser-enforced barrier by preventing cross-origin `fetch`/`XMLHttpRequest` calls with credentials from reaching the server.

## What it defends against

See [Cross-Site Request Forgery (CSRF)](../../attack/csrf.md).

In this app, the threat is an attacker-controlled page issuing a forged `POST` to `/api/auth/logout`, `/api/auth/refresh`, `/api/auth/login`, or `/api/auth/register` while a user holds a valid `prismatica_refresh` cookie. A successful forgery could log the user out, steal a refresh token, or register a shadow account tied to the victim's session.

## How opposite-osiris implements it

**1. `SameSite=Lax` + `HttpOnly` + `Secure` on the session cookie**

[`apps/opposite-osiris/scripts/auth-gateway.mjs`](../../../../apps/opposite-osiris/scripts/auth-gateway.mjs) — lines 158–164 define both the set and the clear helpers for the sole session credential:

```js
function refreshCookie(token, maxAge = 60 * 60 * 24 * 30) {
    return `prismatica_refresh=${encodeURIComponent(token)}; HttpOnly; SameSite=Lax; Secure; Path=/api/auth; Max-Age=${maxAge}`;
}
function clearRefreshCookie() {
    return 'prismatica_refresh=; HttpOnly; SameSite=Lax; Secure; Path=/api/auth; Max-Age=0';
}
```

`SameSite=Lax` means the cookie is withheld on cross-site sub-resource requests and `POST` navigations, so a forged form submit from a third-party origin never carries the token. `HttpOnly` prevents JavaScript exfiltration; `Secure` limits transmission to TLS.

**2. Single-origin CORS allowlist — no wildcard, credentials required**

The same file, lines 1143–1147, handles every `OPTIONS` preflight:

```js
if (request.method === 'OPTIONS') {
    response.writeHead(204, {
        'access-control-allow-origin': config.siteUrl,   // single configured origin
        'access-control-allow-credentials': 'true',
        'access-control-allow-methods': 'GET, POST, OPTIONS',
        'access-control-allow-headers': 'content-type, authorization'
    });
    response.end();
    return;
}
```

`config.siteUrl` is a single value derived from the `PUBLIC_SITE_URL` environment variable at startup; it is never `*`. Browsers therefore block credentialed cross-origin `fetch` calls from any other origin before the request body reaches the server.

**3. Cloudflare Turnstile token on all auth mutations**

[`apps/opposite-osiris/scripts/auth-gateway.mjs`](../../../../apps/opposite-osiris/scripts/auth-gateway.mjs) — `verifyTurnstile()` (line 225) validates a Cloudflare server-side siteverify response for every login, register, and recover action (line 697). The token is a short-lived, single-use proof of browser interaction generated by the Cloudflare widget on the client. An attacker cannot forge it from a third-party page, adding a second independent barrier even if `SameSite` were bypassed.

## How we know it is applied

[`apps/opposite-osiris/scripts/security/01-cors.mjs`](../../../../apps/opposite-osiris/scripts/security/01-cors.mjs) is a live security-assertion script that exercises the running gateway. Lines 53–71 contain two explicit assertions:

```js
// disallowed origin is not echoed
assert.notEqual(response.headers.get('access-control-allow-origin'), config.disallowedOrigin);

// no wildcard with credentials
assert.equal(response.headers.get('access-control-allow-credentials'), 'true');
assert.notEqual(response.headers.get('access-control-allow-origin'), '*');
```

These assertions are not unit mocks — they fire `OPTIONS` preflights against the live gateway and fail the process if either invariant breaks. The script verifies that a disallowed origin is not reflected and that a credentialed response never carries a wildcard `Access-Control-Allow-Origin`, which is the exact property that CSRF protection requires from CORS.

## Reference

The [CSRF Prevention Cheat Sheet (OWASP)](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) catalogues both token-based and cookie-attribute-based mitigations, including the `SameSite` guidance and the conditions under which CORS can substitute for a synchronizer token. This implementation follows the cookie-attribute path (§ "Using Same-Site Cookies") and augments it with a Turnstile challenge that serves the same role as a server-generated per-request token for unauthenticated state-changing endpoints.

## Residual risk / assumptions

- **`SameSite=Lax` browser support is assumed.** Very old browsers (pre-2019) that ignore `SameSite` would reduce the defense to CORS alone. The Turnstile requirement on auth mutations partially compensates.
- **CORS only blocks browser fetches.** A server-side SSRF, a misconfigured proxy, or a direct `curl` from the attacker's server bypasses CORS entirely; the cookie is not forwarded in those cases but the Turnstile check would also fail (no valid token).
- **Turnstile bypass is possible in local/dev mode** via `TURNSTILE_BYPASS_LOCAL=true`. This is correctly gated on the `localhost-turnstile-token` sentinel value, but deployments must ensure this env var is not set in production.
- **No explicit synchronizer (double-submit) token.** If `SameSite` support degrades (e.g., a same-site subdomain takeover allows same-site framing) the CORS allowlist and Turnstile remain, but traditional anti-CSRF token defense-in-depth is absent.
- **`Path=/api/auth` scoping** limits the cookie to the auth sub-path; any credential-free endpoints on other paths are not covered by this cookie, though they have no session to forge against.
